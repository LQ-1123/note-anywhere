# 表格功能 · 现状与下一步需求

> 版本基线：v1.4.0（源码工作区，未发布）。本文档记录表格功能的当前实现状态、
> 尚未解决的问题、下一步需求与验收标准，以及调试过程中确认过的技术坑，
> 供下一轮开发直接上手，避免重蹈覆辙。

---

## 一、用户原始诉求

1. `/bg` + 回车 → 直接得到**渲染好的表格**（不是管道源码）
2. **在渲染出来的表格里直接编辑**（所见即所得），不要跳回源码
3. 表格可以**增加/删除行和列**
4. 斜杠菜单：**↑↓ 选择，空格或 Tab 确认**

## 二、当前已实现（v1.4.0 工作区）

代码位置：`renderer/src/app.js`（表格相关函数均已实现）、`renderer/style.css`、
`main.js`（win-visibility 推送）、`preload.js`（onVisibility 通道）。

### 2.1 渲染方案（已定型，勿推翻）

- **行内逐行替换**（不是块级装饰）：光标在表外时，表头行整行替换为表格卡片组件
  （`TableWidget`），分隔行/数据行整行隐藏 + CSS 塌陷（`.cm-table-hidden`）
- 光标进入表格任意行（键盘导航）→ 源码态，整表浅底标识（`.cm-table-line`）
- 兼容 `\|` 转义、列数不齐的行（渲染时补齐）

### 2.2 卡片内编辑（已实现）

- 单元格为 `contenteditable=plaintext-only` 的 `div.cm-tb-edit`，点击原生聚焦
- 输入 350ms 防抖后整行写回 Markdown 源码（`syncTableCell`），打字期间组件 DOM 不重建
  （`TableWidget.eq` 在 `tableLiveEdit` 激活时只比较结构，保焦点）
- 单元格内：`Enter` 下方加行并聚焦同列、`Tab`/`Shift+Tab` 逐格跳（末格 Tab 加行）、
  `Esc` 回正文、`Ctrl+Z` 转发给编辑器撤销
- 悬停表头 `+`/`×` 增删列、悬停行首 `+`/`×` 增删行、卡片底部「＋行 / ＋列」；
  结构操作后自动聚焦新格（`tableStructOp` 的 focus 参数）
- 删最后一列 = 删除整表；结构改动均为一次撤销步骤

### 2.3 斜杠菜单（已实现）

- ↑↓ 选择 + 高亮（原有）；**新增空格确认**；回车/Tab 确认（原有）；Esc 关闭
- `/bg` 插入表格后：光标放在表尾（表外），260ms 后自动聚焦第一个表头格（`applySnippet`）

### 2.4 安全机制（血的教训，勿删）

- **渲染门控** `tableRenderOk`：由主进程 `win-visibility`（show/hide 事件）驱动，
  变可见后需 `requestAnimationFrame×2 + 200ms` 才放行卡片渲染。
  原因：隐藏/未激活窗口里组件测量会**自旋卡死渲染进程**（详见第五节坑 2-4）
- 表格行不参与行内 HTML 扫描（`buildMdDecos` 的 `hiddenLines`）
- 表格外上/下方行的退格/删除保护（`tableDeleteGuard`：落入首格/末格，不拼坏表格）

### 2.5 冒烟与诊断

- `npm run smoke` / `npm run diag`：通过 `tools/smoke-bootstrap.js` 运行
  （独立 userData + 临时笔记目录 + 独占热键，不与常驻实例冲突）
- 探针（`tools/smoke-bootstrap.js` 内置，环境变量开关）：
  - `SMOKE_USER_PROBE=1`：模拟「show() 后恢复含表格笔记」的真实用户路径，探活 + 查卡片数
  - `SMOKE_USER_PROBE=hidden`：隐藏窗口推表格（预期：不渲染但存活）
  - `SMOKE_CPUPROF=1`：卡死时抓 CPU profile

## 三、当前阻塞问题（P0，已解决）

### 现象

用户实际操作「输入 `/bg` 回车」后，表格曾显示为管道源码，未渲染成卡片。

2026-10-04 已完成修复：真实键鼠回归确认 `/bg` 回车在 1 秒内渲染表格并聚焦首格；收起/呼出、重载恢复、无 `requestAnimationFrame` 环境也通过。

### 已确认的事实（同机实测）

| 实验 | 结果 |
| --- | --- |
| 探针：show() → 立即 send restore(表格文本) → 探活 | ✅ 存活，`.cm-table-wrap=1`（卡片渲染成功，3/3 次） |
| 纯 `npm run smoke` | ✅ 通过 |
| `npm run diag`（本机远程桌面环境） | ⚠️ 冒烟通过，但 DIAG 超时（诊断窗口的 rAF 不触发） |
| 用户手工 `/bg` 交互 | ❌ 不生效（文档里停着字面量 `/bg`，表格根本没插入） |
| 渲染进程报错 | 无（console 干净） |

> ⚠️ 2026-10-04 复核更正：当时把现象描述为「表格显示成管道源码」是误判。
> 用户笔记里留下的是**字面量 `/bg`**（4 字节、无尾换行），即回车从未生效，
> 表格源码压根没被插入过。真正的根因不是 H1（渲染门控），见下方「真实根因」。

### 根因假设（按可能性排序）

- **H1 渲染门控未打开**：`tableRenderOk` 依赖「win-visibility IPC → rAF×2 → 200ms」链。
  本机为远程桌面/受限合成器环境，rAF 可能长时间不触发（diag 超时即同款现象），
  门永不开 → 卡片永不渲染。探针能过是因为 show+restore 路径上 rAF 恰好触发过。
- **H2 焦点/光标停在表内**：源码态（浅底）是设计行为。/bg 后聚焦逻辑若失败
  （260ms 内卡片未就绪），用户可能停留在源码态。需区分「表内源码态（正常）」与
  「表外仍不渲染（故障）」。
- **H3 IME 干扰**：中文输入法下 `/bg` 的回车可能先提交候选词；空格确认可能被 IME 吃掉。
- **H4 版本未生效**：可能性低（已重启、APP-READY 正常），验证方法见第六节。

## 三之二、真实根因（2026-10-04 复核确认并修复）

**现象**：中文输入法下输入 `/bg`，斜杠菜单已正确筛出「表格」，但按回车后文档停在
字面量 `/bg`，表格不插入、不渲染，且没有任何报错或提示。

**根因（已在 CodeMirror 源码层面确认）**：`@codemirror/view` 的
`DOMObserver.ignoreDuringComposition()` 规定：

```js
if (!/^key/.test(event.type) || event.synthetic) return false;
if (this.composing > 0) return true;   // 组合期间丢弃全部 key 事件
```

中文输入法下 `bg` 处于组合态，这一次回车是**输入法用来上屏的**，被 CM 的观察器
直接丢弃 —— 应用的 `Prec.high(domEventHandlers)` keydown 与 keymap 都收不到，
`handleSlashKey` 永远不会被调用。上屏后用户需要再按一次回车才生效，而单按一次
就是「什么也没发生」。

**修复**（`renderer/src/app.js`）：

1. `editorHost` 的 **DOM 捕获阶段** keydown 旁听组合态的**回车 / 空格 / Tab**（空格是中文
   输入法最常用的上屏键），只记下确认意图（`slash.pendingConfirm` 时间戳），不抢先插入；
2. `document` 的 `compositionend` 之后，按**最新文档**重新核对查询词，仍匹配才
   `applySnippet`。这样两类误插都被挡住：中文候选上屏（查询词变中文 → 菜单已关闭）、
   以及在组合中途按空格选词的情况；
3. 回归用例已并入 `tools/table-regression.js`：
   - `/bg confirmed by IME composition commits and renders`（回车）
   - `/bg confirmed by IME space commit, and Chinese commit does not insert`（空格 + 中文候选不误插）

**顺带修复的两个独立缺陷**（同一轮，均有回归覆盖）：

- **Esc 关不掉设置面板**：`settingsOpen && Escape → closeSettings()` 只写在 CM 的
  keydown 里，而面板打开时焦点在面板控件上，编辑器收不到按键 → 面板关不掉。
  已改为在 `document` 捕获阶段兜住（录制热键时让给热键逻辑）。
- **关闭面板后焦点丢失 / 表格聚焦意图被吞**：点设置按钮的 mousedown 会取消
  `/bg` 插入后的自动聚焦重试，关掉面板后焦点停在头部按钮上（Tab 还会往正文里
  插制表符）。已记录 `settingsReturnFocus` 与 `tableFocusIntent`，关面板时归还焦点
  并续上未完成的单元格聚焦；用户期间移动过光标则不抢焦点。

**验收**：`npm run test:tables` 全绿（5 项门控单测 + 20 项真实键鼠回归，连续 3 次）。

> 环境提示：`npm run test:tables` 里的 `electron tools/...` 若因环境变量
> `ELECTRON_RUN_AS_NODE=1`（有的宿主 shell 会注入）而被当成普通 Node 运行，
> 会以 `TypeError: Cannot read properties of undefined (reading 'setPath')` 失败，
> 与本项目无关。跑测试前 `Remove-Item Env:\ELECTRON_RUN_AS_NODE` 即可。

**状态：已完成。**

**验收标准**：打开应用 → 新页输入 `/bg` 回车 → **1 秒内**出现渲染表格，

## 五、已知技术坑（下一轮开发必读）

1. **块级替换装饰（`Decoration.replace({block:true})`）禁止由 ViewPlugin 提供**，
   会抛 `RangeError: Block decorations may not be specified via plugins` 并损坏视图。
   StateField 提供虽合法，但块级组件在窗口状态不稳时仍会测量自旋——**最终方案
   是行内逐行替换，勿改回块级**。
2. **隐藏窗口（show:false 创建、从未显示）里 DOM 撒谎**：`document.hidden` 误报
   `false`、rAF 照跑、布局全零。此时任何组件（代码卡片 LnWidget、表格卡片）参与
   测量 → 渲染进程同步死循环 → 主进程对窗口的原生调用（setBounds 等）一并卡死。
   v1.3.1 的 `--smoke --diag` 在本机就卡（已用 git stash 验证与表格功能无关）。
3. **showInactive（未激活）窗口**：合成器不产出真实布局 → 同样自旋。
4. **屏幕外（-3000）+ show()**：遮挡检测节流 rAF → 不自旋但也不渲染（diag 超时的原因）。
5. **结论**：组件渲染只信主进程的 `win.isVisible()`（show/hide 事件推送，
   `preload.onVisibility`）。真实用户路径里 restore 紧跟 show()，门控兜底见 P0-1。
6. **lezer `iterate` 的 `enter` 返回 `false` 会剪枝整个子树**：在 Document 根上
   对非目标节点 `return false` = 永远访问不到目标。应 `return`（undefined）继续下降，
   处理完目标再 `return false` 跳过其子节点。
7. **单实例锁 + 全局热键占用**：常驻实例运行时直接 `electron . --smoke` 会被锁掉或
   弹原生错误框卡死。冒烟一律走 `tools/smoke-bootstrap.js`。
8. **远程桌面/无 GPU 合成器**：可见窗口的 rAF 也可能不触发 → 依赖 rAF 的逻辑必须有
   定时器兜底。
